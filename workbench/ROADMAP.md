## Original cumulative Gates A-E

These original criteria are retained, not weakened. Their first-milestone history and detailed prior backlog are preserved byte-for-byte in [ROADMAP_BASELINE.md](ROADMAP_BASELINE.md); the historical progress ledger is [PROGRESS_HISTORY.md](PROGRESS_HISTORY.md). Both snapshots describe past checkpoints, not the active status below.

### Gate A — evidence core
- Final reports are integrity-checked before persistence/export.
- Failed/skipped/inconclusive checks remain visible and cannot become successful coverage.
- Scanner imports cannot self-promote observations to independently verified findings.
- Synthetic proof has a denied control and fresh canary, and is never attributed to an external target.

### Gate B — reliability boundary
- One enforceable end-to-end deadline covers resolution, connect, TLS, response and model operations.
- Cancellation is tested in every phase and cannot publish an unsealed terminal report.
- Crash/restart recovery cannot expose a running job as completed.
- Terminal report publication and durable persistence are atomic or explicitly marked non-durable.

### Gate C — adapter and scope boundary
- Versioned adapter contracts reject malformed/truncated/oversized output and disclose exact coverage.
- Execution adapters use typed configuration, fixed binaries/images and independent scope/effect/request limits; no model-generated shell strings.
- At least one read-only project adapter and one bounded web adapter pass vulnerable/fixed synthetic fixtures before broader claims.

### Gate D — retest and reviewer evidence
- Cross-run comparison distinguishes still-present, new, not-reproduced and not-retested; absence alone never means fixed.
- Reviewer bundles contain checksummed report artifacts and safe proof metadata without reusable credentials or ordinary customer-row samples.
- Remediation evidence links to a comparable recheck and preserves changed-scope/failed-scanner states.

### Gate E — usable review release
- Real-model compatibility is tested separately from protocol doubles; processing location/usage remain honest.
- Browser-to-server E2E and keyboard/accessibility flows pass on documented browsers.
- Fresh-install smoke tests pass on the documented platforms with pinned dependencies/tool licenses and an SBOM.
- Threat model, sample reports, regression lab catalog and release notes clearly separate implemented, experimental and unsupported coverage.

## Ordered substantive workstreams

1. **Current defects and review contract.** Repair contradictory docs and CI setup, add meaningful regressions, preserve the complete old ledger and explicit current revision/results. The package path stays independent of legacy installers/dependencies.
2. **Reliability.** Continue DNS/connect/TLS/response/model cancellation and deadlines; test concurrent API activity and storage failures/checkpoint gaps. Atomic publication must remain sealed or explicitly non-durable. No claim that cooperative filesystem/OS resolver work is instantly preemptible.
3. **Adapter boundaries.** Preserve typed declarations, exact request-digest approval, lifecycle recovery and candidate-only receipts. The native metadata adapter and bounded single-HEAD adapter exist. Semgrep CE 1.177.0 is the one reviewed pinned offline third-party runner. Trivy/Nuclei are parser-only; ZAP/Nmap execution is absent. Review versions/licenses/checksums/sandbox/offline fixtures before new runners; no dynamic command strings or arbitrary execution.
4. **Useful assessment/report integration.** Adapter receipts are an independent audit trail, not automatically part of the main assessment report. Any explicit candidate import must preserve provenance, coverage, authority and request/effect limits. Report absence never becomes fixed or safe.
5. **Controlled role contexts.** The execution-neutral access matrix exists. A designated test-role runner remains unimplemented and needs scoped synthetic records, local credential isolation/expiry/redaction, independent denied controls and bounded execution. No credential harvesting or ordinary customer-row extraction.
6. **Responsive review UX.** Actual adapter plan/approve/execute and retest/export controls exist. Add useful progress, evidence drill-down and cancellation/focus-state tests without automatic inference/execution or redundant modules. Chromium/Ubuntu E2E is separate from DOM tests; broader browser and manual assistive-technology review remain unimplemented.
7. **Models and maintenance.** Extend capability/invalid-output/privacy compatibility evidence and separately evaluate usefulness before quality claims. One real tiny local model is not a benchmark. Public reference/model downloads require reviewed source/license/integrity/version/freshness/rollback and no assessment data. Runtime upgrades, model downloads, RAG refresh and fine-tuning are distinct. Training requires separate approved data/evaluation; no self-modification.
8. **Release and wider review.** Preserve exact-byte package smoke, SBOM, provenance attestations, threat model, sample reports and regression catalog. Portable source archive is not native installation/signing or signed assessment handover. Make review coherent rather than inflating commit count; acceptance/investment/stars are external outcomes.
